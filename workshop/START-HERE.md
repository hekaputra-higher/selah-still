# Start here

Something exists when you leave tonight that did not exist when you arrived.

1. What are you building? One sentence.
2. Who is it for? One person and their situation.
3. What problem does it solve? One concrete moment.
4. What is the smallest useful version? One complete journey.
5. What context does your AI need? Purpose, constraints, design and what it must never do.
6. Ask it to plan before coding. Correct the assumptions.
7. Build one useful slice.
8. Test it: expected result, wrong input, mobile, keyboard and privacy.
9. Deploy if you can. Review a preview before release.
10. Learn: ask someone to try it and choose the next small improvement.

## Copy and fill in

“I want to build [idea] for [person] who needs [need]. Tonight the smallest useful version is [journey]. It must [constraints] and must never [anti-goals]. Ask up to three useful questions, then propose a plan. Do not code yet.”

Next: “Implement only the first useful slice. Tell me what changed and run the checks that show it works.”

Review: “Try to break this flow. Check errors, mobile, accessibility and any private data. Separate verified evidence from assumptions.”

New to building: clarify the idea and create one working screen. Comfortable: build a feature, use Git and deploy if possible. Experienced: explore architecture, Auth, persistence and access rules. Supabase is optional for your idea tonight.

Use a tool you already have access to. If local setup takes more than five minutes, pair with someone or use a browser-based builder. Never paste work credentials or real private data into a demonstration.
